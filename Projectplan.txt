1. Executive Summary & Microservices Architecture 
Overview 
This document outlines the engineering architecture for your new ful-stack Supply Chain and 
Inventory Management System, refactored into a scalable microservices architecture. While 
retaining the robust foundation of your PHP 8.2 backend, vanila JavaScript/HTML/CSS 
frontend, and MariaDB database, the application is partitioned into independent, decoupled 
service containers coordinated via an API Gateway and container networking. 
Technology Stack & Microservices Specifications 
● Frontend Container (frontend-service): HTML5, Vanila JavaScript (ES6+), CSS3 with 
Tailwind CSS (preserving the exact indigo/blue theme, rounded sidebar navigation, badge 
styles, and typography shown in your layout reference). Serves static assets and 
communicates with the backend via REST and WebSockets. 
● API Gateway & Routing (gateway-service): Centralized entry point handling request 
routing, JWT/Session authentication verification, rate limiting, and CORS headers. 
● Core Services (Containerized PHP 8.2 / Apache / Slim or Vanilla PHP micro-apps): 
1. auth-service: User management, MFA/TOTP, RBAC, session management, and login 
audit logs. 
2. inventory-service: Asset tracking, smart warehouse occupancy grid, and stock 
transfers. 
3. procurement-service: Purchase orders, supplier scorecards, sourcing pipelines, and 
PDF generation. 
4. logistics-service: Document tracking, EAF compliance, and mobile scan feed 
processing. 
● Real-Time Sync: Dedicated WebSocket microservice (Ratchet PHP) handling live stream 
updates between warehouse mobile scanners and the desktop command center without 
page refreshes. 
● Database Layer: Managed MariaDB instances partitioned logicaly per service (or sharing 
a secure managed cluster with strict database user isolation). 
● Version Control & CI/CD: Git & GitHub integrated directly with hostforgeplatform.cloud 
using Docker Compose multi-container deployments or individual container orchestration.

3. Core Modules & Microservice Mapping 
A. The 6 Core Modules Breakdown 
1. Smart Warehousing System (SWS): Managed by inventory-service. Real-time occupancy 
grid mapping zones, rows, and shelves (colored Red/Yelow/Green based on capacity 
limits), plus QR code physical bin tracking. 
2. Inventory Management System (IMS): Managed by inventory-service. Tracks individual 
IT hardware assets (Laptops, Monitors, Peripherals), valuation, and status (Deployed, In 
Warehouse, In Maintenance). 
3. Procurement & Sourcing Management (PSM): Managed by procurement-service. 
Requisitions, supplier quotes, and sourcing pipelines. 
4. Supplier/Vendor Management (SVM): Managed by procurement-service. Performance 
scorecards tracking On-Time Delivery Rate and Device Defect Rate. 
5. Purchase Order Management (POM): Managed by procurement-service. PO Lifecycle 
Pipeline (Draft  Pending Approval  Sent to Vendor  Shipped  Received). 
Automatica ly triggers QR PDF generation upon receiving. 
6. Document Tracking & Logistics Record System (DTRS): Managed by logistics-service. 
Equipment Accountability Form (EAF) compliance tracking, digital signatures, courier 
receipts, and invoice verification. 
(Note: The Dashboard operates as the unified command center link above these 6 core 
modules). 
B. Microservices Database Schema Boundaries 
● Auth & User DB (auth_db): users, api_tokens, roles, permissions, login_history. 
● Inventory & Warehouse DB (inventory_db): warehouse_shelves, assets, 
asset_transactions. 
● Procurement & Vendor DB (procurement_db): vendors, purchase_orders, 
purchase_order_items. 
● Logistics DB (logistics_db): document_logs, audit_logs. 
4. Easy REST API & Gateway Integration Layer (/api/v1/) 
Al requests route through the API Gateway, exposing clean JSON endpoints: 
● POST /api/v1/auth/login — Handled by auth-service (MFA/TOTP validation, token issuance). 
● GET /api/v1/assets/{qr_code} — Handled by inventory-service. 
● POST /api/v1/assets/scan — Handled by inventory-service & broadcasted via WebSocket. 
● GET /api/v1/pos/pending & PUT /api/v1/pos/{id}/status — Handled by procurement-service. 
5. Security Enhancements: RBAC & Inactivity Timeout 
● Role-Based Access Control (RBAC): Enforced at the API Gateway level based on JWT 
claims and user roles (Admin, Manager, WarehouseStaff). 
● Automated 30-Minute Inactivity Timeout: Client-side activity monitoring with a warning 
modal at 27 minutes, backed by server-side session/token invalidation across 
microservices.
