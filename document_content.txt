 SCIM Code Audit and Fix Guide Great Solomon Supply Chain Services Based on the supplied source files, project documents, and implementation notes This document summarizes the confirmed defects found in the supplied SCIM codebase, the fixes prepared for the core modules, and the deployment steps needed to apply them safely. 1. Confirmed Code Defects and Fixes Area Defect in supplied code Fix in the prepared package Inventory MariaDB DECIMAL values could concatenate in JavaScript and show ₱NaN. Explicit Number(...) conversion for totals and categories. Detail/View buttons API detail routes returned a row directly while JavaScript expected wrappers such as response.asset. Detail routes now return consistent wrappers and JavaScript accepts either shape. Inventory Edit Button displayed "to be implemented". Added a PUT route and a working edit flow. Procurement Edit Button displayed "to be implemented". Added a PUT route and a working edit flow. Supplier rendering rating.toFixed() could fail because PDO can return DECIMAL as a string; averages could concatenate strings. Numeric conversion added throughout. Supplier Edit Button displayed "to be implemented". Added a PUT route and a working edit flow. Purchase Orders Vendor select contained hard-coded IDs and names unrelated to the live vendors table. Vendor list is loaded from /api/v1/suppliers. Purchase Orders User-entered PO number was ignored by PHP. Supplied PO number is retained; a number is generated only when blank. PO activity An earlier duplicate status route returned before the activity-logging route, so status changes were not logged. Removed the shadowing route; status changes now write to po_activity. PO totals DECIMAL totals could concatenate in monthly and vendor totals. Explicit numeric conversion. Documents User-entered reference number was ignored by PHP. Supplied reference number is retained; generated only when blank. Documents Detail response shape did not match viewDocument(). Consistent wrapper response. Seed data Seed document types did not match frontend filters (EAF, Receipt, Invoice). Seed values normalized. Seed data Requisition seeds assumed user ID 1 before any user existed. Seed rows use nullable created_by; API migration creates a default admin. Legacy database CREATE TABLE IF NOT EXISTS did not add columns to existing old tables. Runtime migration checks and creates required columns; schema_patch.sql is included for manual use. Authentication Most module Logout buttons only navigated away and left the server session alive. Logout now POSTs /auth/logout. Inactivity Project plan calls for a 30-minute timeout and a 27-minute warning. Server timeout plus shared session.js warning and keepalive. Deployment cache Production could continue serving stale JavaScript. Versioned scripts and no-cache headers for HTML/JS. Database config DB port variable was read but not used. Port added to the PDO DSN. Database security Supplied API source contained hard-coded live DB credentials. Removed; environment variables/config file only. Rotate exposed credentials. Scanner Transactions accepted a zone but the UI never sent one. Optional warehouse zone field added to scanner dialogs. 2. Requirements That Are Broader Than This Fix Pack The supplied project blueprint describes a larger target architecture that includes: WebSocket-based real-time synchronization. MFA/TOTP authentication. An API gateway. Independently deployed microservices and service-specific databases. Production-grade monitoring, backups, and CI/CD. Current implementation status: the repository is a modular monolith: HTML/CSS/JavaScript frontend pages, a single PHP API/router, and a MariaDB/MySQL database. Those larger architecture items are separate projects rather than small bug fixes. QR PDF generation: the supplied backend contains only a JSON placeholder for the QR-PDF endpoint. The prepared package prevents the browser from downloading that JSON as a fake PDF and reports the feature as unavailable until a real QR-code/PDF library is added. 3. Deployment Instructions Back up the live MariaDB database before replacing application files. Replace the matching repository files with the files from the fix package. The backend file belongs at api/index.php. For an existing live database, do not re-import init.sql. The PHP migration is designed to repair required legacy columns automatically. Use schema_patch.sql only if you prefer a manual compatibility update. In HostForge, verify DB_HOST, DB_PORT, DB_NAME, DB_USER, and DB_PASS. Rotate the database password because database credentials were previously hard-coded in source. Update DB_PASS after rotating it. On a fresh empty database, set SCIM_ADMIN_EMAIL, SCIM_ADMIN_PASSWORD, and optionally SCIM_ADMIN_NAME before the first request. Commit the changes to the branch HostForge actually deploys, then redeploy. Verify the live JavaScript directly before testing the user interface, for example: https://scim.greatsolomonmpservices.com/inventory.js?v=20260923. Test with an Admin or Manager account: add/edit Inventory, add/edit Supplier, create/edit Requisition, create PO, update PO status, create/sign/update Document, and record a QR scan. Treat QR PDF as unavailable until a real QR/PDF library is installed. 4. Recommended Validation Checklist Inventory totals no longer show ₱NaN. New assets appear in the assets table. Supplier records save to vendors and render without rating.toFixed errors. Purchase Order vendor choices come from the live vendors table. PO status changes create rows in po_activity. Requisition create/edit operations persist in requisitions. Document create/status/sign operations persist in documents, document_activity, and document_signatures. Logout destroys the server session instead of only redirecting. Session warning appears at approximately 27 minutes of inactivity and timeout occurs at approximately 30 minutes. HostForge serves the newest versioned JavaScript after deployment. 5. Important Production Notes Do not overwrite the live database with init.sql after production data already exists. Keep database credentials in HostForge environment variables or a non-committed config file. Change all demo/default passwords before production use. Back up the database before schema changes or deployment. The repository does not yet provide automated tests, full production monitoring, or a complete CI/CD workflow.
